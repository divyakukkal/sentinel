01 — THE PROBLEM

Damage happens before the signature exists.

A new ransomware variant has no antivirus signature on day zero. By the time one is written and distributed, the variant has already walked through the file system — encrypting, renaming, deleting shadow copies — and the damage is done. What every variant does share, though, is behaviour: files change too fast, entropy jumps as plaintext turns to ciphertext, and processes start touching files they've never touched before. Sentinel is built to notice that pattern, not the file hash.

02 — HOW IT WORKS

Five stages, from raw event to explained alert.

1

Collect

A lightweight agent watches file events, process calls and I/O — on safe public datasets and isolated synthetic traces, never live malware.

→
2

Engineer features

Access frequency, rename/delete rate, entropy deltas and I/O pattern windows are computed per host, per minute.

→
3

Classify

Logistic Regression, Random Forest, XGBoost, SVM and a neural model vote on benign vs. malicious, tuned for class imbalance.

→
4

Explain

SHAP / LIME surface exactly which features drove a high-risk call, so an analyst can trust — or override — the alert.

→
5

Warn

The dashboard raises a ranked, explained alert with an event timeline — before large-scale encryption completes.

04 — SEMESTER ROADMAP

Three semesters, one system, built in order.

SEM V

Project I — Foundation

  • Survey ransomware families & behavioural detection literature
  • Define threat model and system architecture (SRS)
  • Acquire & preprocess public benign/ransomware behaviour datasets
  • Feature engineering + baseline ML models
Deliverables — curated dataset, baseline model, threat/feature analysis, SRS, architecture doc, Project-I report
SEM VI

Project II — Detection Engine

  • Advanced ML/DL models with class-imbalance handling
  • Safe event-monitoring agent + detection API
  • SHAP/LIME explainability layer
  • Early-warning logic and controlled validation
Deliverables — detection engine, monitoring prototype, XAI explanations, evaluation report, draft paper, Project-II report
SEM VII

Project III — Product & Publication

  • Full analyst dashboard + model/API optimisation
  • Extensive benign/synthetic workload testing
  • Packaging, documentation, user guide
  • Publication / patent / open-source draft
Deliverables — working early-warning prototype, validated results, user guide, dissertation, publication draft
